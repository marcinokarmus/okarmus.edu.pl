Blok 1 · Akwizycja (11:45–12:30)

1Surowy sygnał 2 pkt

A W Node-RED przeciągnij węzeł mqtt in (kategoria network). Server: Hala 1 (broker), Topic: zaklad/hala1/pak01/TT101_mA, Output: auto-detect. Połącz go z węzłem debug i kliknij Deploy. Wartości pojawią się w zakładce 🐞 po prawej.
C Zakładka 1. Sygnały ze sterownika.

Zapisz: godzinę, odczytaną wartość w mA i własne przeliczenie na °C (wzór!). Ile °C odpowiada zmianie o 0,01 mA? Jaka jest więc rozdzielczość tego pomiaru?

2Tor akwizycji: skalowanie i jakość 3 pkt

A Za mqtt in wstaw:

  1. switch (function), nazwa „jakość”: reguła < 3.8 (typ number) → wyjście 1 = pomiar zły; reguła otherwise → wyjście 2 = pomiar dobry.
  2. Do wyjścia 2 podłącz range (function): Scale the message property, from 4 – 20 to 0 – 300.
  3. Za range wstaw template (function), Format: Plain text, Output as: Plain text, treść (zamień NN na swój numer!): 
    pak01_sNN temp_c={{payload}},jakosc_temp=1i
    i połącz z gotowym węzłem → HISTORIAN.
  4. Do wyjścia 1 switcha podłącz drugi template: pak01_sNN jakosc_temp=0i → HISTORIAN.
  5. Ciśnienie: drugi mqtt in (…/PT102_reg) → range 0–1000 → 0–10 → template pak01_sNN cisn_bar={{payload}} → HISTORIAN.

Deploy. Pod węzłem „odpowiedź historiana” ma się pokazywać 204 (zapisano). Kod 400 oznacza błąd w linii — sprawdź spacje i przecinki.

Format linii (line protocol): tabela pole=wartość,pole2=wartość — jedna spacja po nazwie tabeli, bez spacji między polami; 1i = liczba całkowita.

C Zakładka 2. Akwizycja: wpisz zakres przetwornika, regułę jakości i mnożnik ciśnienia z dokumentacji. Sprawdź podgląd „mA → °C”.

Pytanie do sprawozdania: co zapisałby historian podczas przerwy w przewodzie, gdyby nie było reguły jakości? (policz: 0 mA → ? °C)

3Martwa strefa 2 pkt

A Między range a template temperatury wstaw węzeł filter (dawniej „rbe”, kategoria function): Mode block unless value change is greater or equal to 0.5, compared to last valid output value. Deploy. Po 10 minutach porównaj w Grafanie (Explore, źródło Hala 1) liczbę zapisów:

SELECT count("temp_c") FROM "pak01_sNN" WHERE time > now() - 10m
SELECT count("temp_c") FROM "pak01_ref" WHERE time > now() - 10m

C Zakładka 2: martwa strefa 0,5 °C; tabela „Historian — ile danych zapisujemy”.

Zapisz: ile % zapisów oszczędza martwa strefa? Ile rekordów na rok dla tego jednego tagu bez niej, a ile z nią? Co tracimy?

Blok 2 · Dashboard (12:40–13:30)

4Ekran dla wybranego odbiorcy 5 pkt

Najpierw wybierzcie odbiorcę (operator, mistrz zmiany, kierownik produkcji, utrzymanie ruchu) i wpiszcie go w tytule. Dashboard musi mieć co najmniej:

  • trend temperatury zgrzewu z zakresem normalnym 168–176 °C A z Waszej tabeli pak01_sNN
  • stan maszyny (oś stanów albo kafel z kolorem)
  • sztuki dobre — z przyrostów, nie surowy licznik (pamiętacie reset z Lab 1?)
  • jeden wskaźnik jakości lub mediów z progami (braki %, ciśnienie)
  • układ i dobór paneli pasujący do odbiorcy (ćwiczenia: HMI ISA-101 — szarość = norma, kolor = odchylenie)

A Grafana: Dashboards → New → New dashboard → Add visualization, źródło Hala 1 (InfluxDB). W kreatorze zapytania: FROM → tabela, SELECT → field(temp_c) mean(), GROUP BY time($__interval). Typ wykresu wybieracie po prawej (Time series, Stat, Gauge, State timeline). Zakres normalny: Thresholds (czerwony, 168 → zielony, 176 → czerwony) + Show thresholds: As lines + filled regions. Zapisujcie (Save dashboard) do folderu Stanowisko sNN.

Trudniejsze zapytania — przełączcie edytor na tryb tekstowy (ikona ołówka) i wklejcie:

-- stan maszyny (State timeline; Value mappings: 1 praca, 2 postój, 3 awaria, 4 przezbrojenie)
SELECT last("stan") FROM "pak01_ref" WHERE $timeFilter GROUP BY time(10s) fill(previous)

-- sztuki dobre w wybranym zakresie czasu, odporne na reset licznika (Stat)
SELECT sum("d") FROM (SELECT non_negative_difference(last("dobre")) AS d FROM "pak01_ref" WHERE $timeFilter GROUP BY time(10s))

-- braki [%] w ostatnich 15 min (Gauge)
SELECT 100 * sum("z") / (sum("d") + sum("z")) FROM (SELECT non_negative_difference(last("zle")) AS z, non_negative_difference(last("dobre")) AS d FROM "pak01_ref" WHERE time > now() - 15m GROUP BY time(10s))

Ustawcie zakres czasu (prawy górny róg) np. Last 1 hour i odświeżanie 5s.

C Zakładka 3. Dashboard: kliknij pole, wybierz typ, dane, okno i progi, „Zapisz panel”.

Blok 3 · Alarmy i zmiana (13:35–14:15)

5Reguły alarmowe 3 pkt

Co najmniej 4 reguły, każda z sensowną nazwą i zwłoką: (a) temperatura za wysoka, (b) uszkodzony czujnik temperatury, (c) ciśnienie „zamrożone” — wartość nie zmienia się od ≥ 30 s, (d) awaria maszyny. Do każdej zapiszcie: co ma zrobić operator, gdy alarm się pojawi.

A Alerting → Alert rules → New alert rule. Zapytanie jak w panelu, poniżej warunek (IS ABOVE / IS BELOW). Okres zapytania (Time range) np. 1 min. Folder: Stanowisko sNN, Evaluation group: nowa, nazwa sNN, co 10s; Pending period: zwłoka. Podpowiedzi zapytań:

(b) SELECT last("jakosc_temp") FROM "pak01_sNN" WHERE $timeFilter          → IS BELOW 1
(c) SELECT spread("cisn_bar") FROM "pak01_ref" WHERE $timeFilter            → IS BELOW 0.001   (Time range: 30 s)
(d) SELECT last("stan") FROM "pak01_ref" WHERE $timeFilter                  → IS WITHIN RANGE 2.5 … 3.5

Na dashboard dodajcie panel Alert list.

C Zakładka 4. Alarmy.

6Karta zdarzeń zmiany 3 pkt

Od 13:35 obserwujcie maszynę. Każde zdarzenie wpiszcie do tabeli: godzina, kiedy Wy je zauważyliście · co było widać (który panel, który alarm) · prawdopodobna przyczyna · co powinien zrobić operator lub utrzymanie ruchu. Nie wszystko, co widać na ekranie, jest awarią maszyny — czasem to awaria pomiaru.
